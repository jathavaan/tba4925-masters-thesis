\section{Software artifacts and reproducibility}
\label{appendix:software-and-reproducibility}

%Academic rewrite
The software supporting this study is organized as three repositories that run as a pipeline, each maintained under the \texttt{kartAI} organization on GitHub: \texttt{doppa-data-contribution} (\url{https://github.com/kartAI/doppa-data-contribution}) publishes the benchmark datasets, \texttt{doppa} (\url{https://github.com/kartAI/doppa}) runs the benchmarks against them, and \texttt{doppa-analytics} (\url{https://github.com/kartAI/doppa-analytics}) reads the recorded results and builds the figures and tables reported in this thesis. The stages are connected through Blob Storage rather than through direct calls, so each stage reads what its predecessor wrote and writes what its successor reads, and a dataset is published once, benchmarked once, and analyzed without being re-derived. The paragraphs below take the three repositories in pipeline order, then state how the reported artifacts are regenerated.

%Academic rewrite
\texttt{doppa-data-contribution} is the data-publishing stage. It is a set of Jupyter notebooks that download Norwegian building footprints and administrative boundaries from public sources: \acrshort{osm} building footprints through Geofabrik, \acrshort{fkb} cadastral building polygons, Microsoft Global ML Building Footprints, and Norwegian municipality boundaries from Geonorge. Each notebook normalizes its source to the shared GeoParquet schema and uploads the result to the \texttt{contributions} container in Blob Storage, and each is self-contained and idempotent, republishing its dataset in place when re-run. The building footprints are the input from which \texttt{doppa} conflates and synthesizes the small, medium, and large size tiers of Section~\ref{system-architecture-and-implementation:data-layer:logical-dataset-and-size-tiers}, and the municipality boundaries are written once as \texttt{municipalities.parquet} for the \acrshort{rq}2 spatial join, so the benchmark framework never re-derives its own inputs.

%Academic rewrite
\texttt{doppa} is the benchmarking framework and the middle stage, and it is the system that Chapter~\ref{ch:system-architecture-and-implementation} specifies in full. It reads the published datasets from Blob Storage and runs the spatial-query workloads through the engines under test, with each query packaged as an independent container image and executed on \acrshort{aci} by the orchestrator described in Section~\ref{system-architecture-and-implementation:orchestration-and-pairing}. The engines and their configurations are set out in Section~\ref{system-architecture-and-implementation:compute-configuration}, and the measurement protocol and cost model in Section~\ref{system-architecture-and-implementation:measurement-instrumentation-and-cost-model}; this appendix does not restate them. What \texttt{doppa} produces is what the analysis stage consumes: per-iteration samples and a per-benchmark cost row, written as Parquet to the \texttt{benchmarks} container in a Hive-partitioned layout that preserves full distributions rather than point averages.

%Academic rewrite
\texttt{doppa-analytics} is the analysis stage. It reads the result Parquet that \texttt{doppa} writes to Blob Storage and computes the reported statistics: the Wilcoxon rank-sum test and the Vargha--Delaney $\hat{A}_{12}$ effect size (Section~\ref{research-design-and-methodology:statistical-analysis:pairwise-comparison-and-effect-size}), the bootstrapped confidence intervals (Section~\ref{research-design-and-methodology:statistical-analysis:uncertainty-quantification}), and the minimum estimator for elapsed time (Section~\ref{research-design-and-methodology:statistical-analysis:summary-statistics-and-the-choice-of-estimator}). A set of notebooks, numbered \texttt{00} through \texttt{05}, drives the data loading, the measurement-quality checks, and the per-\acrshort{rq} analyses, and a plotting module renders the result figures while the table builders emit the accompanying LaTeX fragments. These figures and fragments are the artifacts that are copied into the thesis source.

%Academic rewrite
The reported result figures and data tables are generated by \texttt{doppa-analytics} rather than produced by hand. They are regenerated from the per-iteration result Parquet that \texttt{doppa} writes to Blob Storage, and the resulting image and LaTeX files are copied into the thesis source. The version of each repository used for the reported artifacts is pinned by commit: \texttt{doppa-data-contribution} at \texttt{6bea50e}, \texttt{doppa} at \texttt{a06e9fd}, and \texttt{doppa-analytics} at \texttt{30f1e39}. Checking out these commits and running the analysis stage against the recorded benchmark results reproduces the figures and tables as they appear in this thesis.
